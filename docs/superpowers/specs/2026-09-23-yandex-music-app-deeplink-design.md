# Открытие трека в Яндекс Музыке из Discord

## Цель

Кнопка Discord Rich Presence должна открывать страницу текущего трека в Яндекс Музыке, если для него удалось надёжно определить ID альбома и трека, не нарушая публикацию активности.

## Поведение

- Существующая кнопка «Открыть трек» заменяется на «В Яндекс Музыке» (короткая подпись нужна для ограничения Discord по UTF-8).
- Ссылка кнопки остаётся HTTPS: `https://music.app.link/?actions=deeplink&deeplink_url={URL-кодированный yandexmusic://album/{albumId}/track/{trackId}}`.
- Используются только ID, полученные из единственного точного совпадения поиска. Неоднозначный результат, ошибка сети или неполные данные оставляют активность без кнопки.
- Других кнопок и серверной инфраструктуры не добавляется.

## Поток данных

`TrackResolver` продолжает искать трек по названию и исполнителю, проверять точное совпадение и получать ID альбома и трека. Он возвращает HTTPS-ссылку-посредник Яндекс Музыки. `ActivityMapper` передаёт её в модель активности, а `DiscordIpcClient` отправляет одну кнопку с короткой подписью и URL.

Discord открывает HTTPS-ссылку в браузере по умолчанию. Домен `music.app.link` передаёт ссылку `yandexmusic://` обработчику Яндекс Музыки, зарегистрированному в Windows; при первом переходе браузер может запросить подтверждение запуска приложения. Если приложение или обработчик отсутствуют, у пользователя остаётся веб-страница трека.

## Ограничения и ошибки

Проверка на установленном Discord показала, что прямой URL с пользовательской схемой `yandexmusic://` приводит к отказу RPC и не публикует всю активность. Поэтому Discord получает поддерживаемый HTTPS URL-посредник, а пользовательская схема находится только внутри URL-кодированного параметра. Подпись кнопки держится в пределах 31 байта UTF-8: в поддерживаемом стороннем RPC-клиенте зафиксировано, что подпись размером 32 байта может скрыть активность от других пользователей.

Если поиск Яндекс Музыки не находит ровно один проверенный трек, приложение продолжает показывать название и исполнителя, но не отправляет кнопку. Поле `buttons` в таком случае отсутствует: значение `null` Discord отклоняет вместе со всей активностью. Если Discord отклоняет ссылку-посредник, программа повторяет отправку с обычной веб-ссылкой на трек.

Для треков с несколькими исполнителями поиск выполняется по первому из них, а результат сверяется с полным списком. Неудачный поиск повторяется через 30 секунд. Время начала активности рассчитывается из позиции и момента обновления медиасессии Windows, поэтому счётчик Discord следует за плеером, включая перемотку.

## Проверка

- Собрать приложение в Release-конфигурации.
- На компьютере с установленной Яндекс Музыкой проверить открытие конкретного трека по диплинку.
- Посмотреть активность с другого аккаунта Discord и проверить кнопку, название и переход к текущему треку.
- Убедиться, что при неоднозначном результате или недоступности поиска кнопка отсутствует, а текстовая активность продолжает работать.
- Запустить сквозной тест с имитацией медиасессии, ответа поиска и Discord IPC: проверить обложку, исполнителей, время, кнопку, отсутствие кнопки при неудачном поиске и очистку активности на паузе.

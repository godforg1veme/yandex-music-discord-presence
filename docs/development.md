# Для разработчиков

Программа читает медиасессию Windows, созданную настольным приложением Яндекс Музыки, и передаёт сведения о текущем треке в Discord через локальное IPC-подключение. Публичный Discord Application ID уже встроен в сборку. Пароль, секретный ключ Discord и токен Яндекса не нужны.

## Запуск из исходников

Из корня проекта:

```powershell
dotnet run --project src/YandexMusicDiscord/YandexMusicDiscord.csproj
```

Для проверки с собственным Discord-приложением можно передать `--client-id=ВАШ_APPLICATION_ID`.

## Сборка

```powershell
dotnet publish src/YandexMusicDiscord/YandexMusicDiscord.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o dist/win-x64
```

Готовый файл: `dist/win-x64/YandexMusicDiscord.exe`.

## Тесты

```powershell
dotnet test tests/YandexMusicDiscord.Tests/YandexMusicDiscord.Tests.csproj
```

Тесты включают сквозной сценарий: поддельная медиасессия, ответ поиска Яндекс Музыки и локальный IPC-сервер Discord. Он проверяет обложку, исполнителей, время, кнопку, очистку активности на паузе и публикацию без кнопки, если поиск не дал результата. Реальные приложения эти тесты не запускают.

Для ручной проверки запустите музыку и посмотрите профиль с другого аккаунта Discord: кнопки Rich Presence не отображаются владельцу активности. Проверьте смену трека, паузу, повторное открытие обоих приложений, переход по кнопке и выход из трея.

## Частота обновления и время

Медиасессия Windows опрашивается раз в 2 секунды. Изменённая активность отправляется сразу, а неизменная повторяется раз в 30 секунд. Для счётчика Discord время начала рассчитывается из `Position` и `LastUpdatedTime` медиасессии; при перемотке оно обновляется. Точность зависит от данных, которые Яндекс Музыка передаёт Windows.

## Как находятся обложка и ссылка на трек

Программа ищет по названию и первому исполнителю. Результат принимается только при точном совпадении названия и полного списка исполнителей; при нескольких совпадениях дополнительно проверяются альбом и длительность. Успешный результат кэшируется для трека, а при неудаче поиск повторяется не чаще раза в 30 секунд. Если поиск не дал однозначного результата, Discord получает текст и статический значок без кнопки.

Для кнопки формируется HTTPS-ссылка `https://music.app.link/?actions=deeplink&deeplink_url=...`, где `deeplink_url` содержит URL-кодированный `yandexmusic://album/{albumId}/track/{trackId}`. Discord получает HTTPS URL, а переход может передаться установленному настольному приложению. Если Discord отклоняет эту ссылку, программа повторяет отправку активности с обычным адресом `https://music.yandex.ru/album/{albumId}/track/{trackId}`. Когда ссылки нет, поле `buttons` вообще не отправляется: `buttons: null` приводило к отказу Discord публиковать всю активность.

Этот поиск не является официально документированным API и может измениться. В таком случае текстовый статус продолжит работать. При паузе, остановке и закрытии плеера активность очищается.

## Выпуск

Версия хранится в `src/YandexMusicDiscord/YandexMusicDiscord.csproj`. Тег `v*` запускает `.github/workflows/release.yml`: тесты, сборку одного exe, архив и публикацию GitHub Release. Если есть файл `docs/releases/<тег>.md`, его текст используется как описание выпуска; иначе GitHub создаёт описание автоматически.
